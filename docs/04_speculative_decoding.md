# 投机解码：为什么"猜"能变快，以及它在什么文本上根本没用

> 结论先行：投机解码能成立，不是因为草稿模型准，而是因为**验证 k 个 token 的成本
> 与生成 1 个 token 基本相同**（本机实测 k=5/k=1 的耗时比 1.13；跨多次 run 落在
> **0.94–1.39**，即围绕 1 波动）。而它的收益几乎完全由"文本可预测性"决定：
> 同一个草稿器，在散文上接受率 **4.4%**，在代码上 **91.5%**，差 20 倍。

---

## 1. 问题：decode 阶段 GPU 在等数据

自回归解码每步只出一个 token，而每步都要把整个模型的权重读一遍。
1.5B 模型 fp16 约 3 GB，一个 token 的算术量却是 GFLOP 级——
算术强度低到必然 memory-bound。

推论（本项目的核心观察）：**一次前向算 1 个 token 还是 5 个 token，
耗时几乎一样，因为限制项是权重读取次数，不是 FLOPs。**

实测（Qwen2.5-1.5B-Instruct, fp16, 本机 RTX 4050；各长度交错测 3 轮取最小值，
并归一化到 L=1，以消除整机吞吐漂移）：

| 一次前向的长度 | 1 | 2 | 3 | 5 |
|---|---|---|---|---|
| 耗时 | 49.80 ms | 69.09 ms | 47.54 ms | 56.26 ms |
| 相对 L=1 的比值 | 1.00 | 1.39 | 0.95 | **1.13** |

**k=5 与 k=1 的比值是 1.13。** 关键不是这个数小于 1，
而是它**在 1 附近**：跨三次独立 run，该比值分别是 1.35、0.94、1.13。
即"多算 4 个 token"的代价远小于 5 倍，基本被带宽吸收。

这就是投机解码的物理基础：验证 k 个候选的边际成本极低，
只要其中平均能接受 >1 个，净收益就是正的。**它赚的是带宽，不是算力。**

## 2. 正确性：为什么"猜"不会改变输出分布

这是整个方法最该讲清楚的一点，也是面试最容易翻车的地方。

### 2.1 算法

草稿模型 q 先猜 k 个 token `x_1..x_k`，目标模型 p 一次前向验证：

```
对每个位置 i：
    接受概率 = min(1, p(x_i) / q(x_i))
    以该概率接受；一旦拒绝，从修正分布
        p'(x) ∝ max(0, p(x) - q(x))
    采样，然后整轮结束。
若 k 个全接受：额外从 p 采一个 bonus token。
```

**关键在"修正分布"那一项。** 少了它，输出分布就会偏向草稿模型的偏好。

### 2.2 实测验证（V=8 的离散分布，200000 次采样）

| 实现 | L1 距离 | 最大绝对误差 | χ² (dof=7) | 判定 |
|---|---|---|---|---|
| 正确实现（拒绝 + 残差） | **0.0038** | 0.0012 | **4.15** | 通过（临界值 14.07） |
| 朴素：直接接受草稿 token | 0.6005 | 0.2000 | 113843 | **崩** |
| 朴素：拒绝但不做残差修正 | 0.2088 | 0.0795 | 10259 | **崩** |

噪声下限：把 200000 次采样随机劈成两半，两半之间的 L1 距离是 **0.0087**。
正确实现的 0.0038 **低于噪声下限**——也就是说它和真实分布的差异测不出来。

理论接受率 0.70，实测 0.69935。

两个"看起来合理"的简化都被否掉了，这比只说"我实现了正确版本"有力得多：
- 直接接受：省掉拒绝逻辑 → 分布偏移 0.60
- 只拒绝不修正：省掉残差采样 → 偏移 0.21

### 2.3 树状注意力

EAGLE / Medusa 会把 k 条草稿链组织成树，公共前缀只算一次。
`tree.py` 里实现了树的构造与 mask，mask 只允许位置 i 看到**自己的祖先链 + 自己**。

`tree_attention_mask` 的测试是 PASS（`results/spec_correctness.json` 的
`tree_mask_test`）。这一条我不是"写了就算"，是断言了非祖先位置确实被 mask 掉。

## 3. 加速比：公式、验证、和"k 不是越大越好"

### 3.1 公式

```
每轮期望接受 token 数 = (1 - α^(k+1)) / (1 - α)        α = 接受率
加速比 S = (1 - α^(k+1)) / ((1 - α)(1 + k·c))          c = 草稿成本/目标成本
```

上界是 `1/(1-α)`：α=0.9 时最多 10×，α=0.5 时最多 2×。**α 决定天花板。**

### 3.2 理论与蒙特卡洛的一致性

18 个 α × 4 个 k × 3 个 c = **216 组配置**，每组 100000 轮模拟：

- 最大相对误差 **0.36%**
- 说明公式与实现自洽（不是"公式写了一个、代码跑的是另一个"）

### 3.3 拐点：54 组里有 53 组的最优 k 小于 32

`(1-α^(k+1))` 很快饱和到 `1/(1-α)`，但分母 `(1+k·c)` 线性增长。
所以 k 一定有个最优值，**超过它加速比会掉回去**。

| α | c（草稿成本比） | 最优 k | 峰值加速 | k=1 时 | k=32 时 |
|---|---|---|---|---|---|
| 0.8 | 0.05 | **8** | 3.09× | 1.71× | 1.92× |
| 0.8 | 0.3 | **3** | 1.55× | 1.38× | **0.47×**（比不投机还慢） |
| 0.9 | 0.05 | **13** | 4.67× | 1.81× | 3.73× |
| 0.9 | 0.1 | **10** | 3.43× | 1.73× | 2.31× |
| 0.9 | 0.3 | **5** | 1.87× | 1.46× | 0.91× |

最刺眼的一行是 α=0.8、c=0.3、k=32：**0.47×，比老老实实自回归还慢一倍。**
"k 调大一点总没坏处"是错的，`c` 一大，k 必须小。

这条对工程的意义很直接：草稿模型不能太贵。c=0.3 时最优 k 只有 3–5，
你几乎拿不到 α 带来的好处——这也是为什么 EAGLE 要花力气把草稿**做成单层**、
Medusa 用多个轻量 head 而不是一个小模型。

## 4. 真实工作负载：同一草稿器，差 20 倍

用 **prompt-lookup 草稿器**（不需要草稿模型：从上下文里找最长匹配后缀，
把后续 n-gram 当作草稿）。2000 token 的中英混合文本，分四段，k=3。

| 文本类型 | 接受率 |
|---|---|
| 散文（中英混杂） | **4.4%** |
| 结构化日志 | 63.8% |
| JSON 块 | 66.4% |
| 代码 | **91.5%** |

这个结果比任何加速比数字都有信息量：

- 散文上 4.4% 的接受率意味着 `1/(1-α) ≈ 1.05`，**基本没有收益**，
  甚至可能为负（还要付草稿成本）
- 代码上 91.5% 的接受率意味着理论上界 `1/(1-α) ≈ 11.8×`

**投机解码的收益由"下一段文本是否可预测"决定，不由硬件决定。**
所以它在代码补全、结构化输出、RAG 引用复述上很强，
在开放创作上很弱。这也解释了为什么几乎所有投机解码论文都在
HumanEval / 代码 / 摘要这类任务上报数，而很少报开放式对话。

（这里测的是 **oracle 接受率**：把原文当作目标模型的输出，度量草稿能命中多少。
它是 prompt-lookup 加速比的上界，不含任何模型权重。）

## 5. 端到端实测：只有 1.05–1.18×，以及为什么

用 Qwen2.5-1.5B-Instruct 真跑 96 个 token（temperature=1.0 采样）：

| 场景 | 每步 token 数 | 接受率 | 实测加速（最优 / 5 次均值） |
|---|---|---|---|
| 重复性文本，k=3 | 2.85 | 63.6% | 1.21× / 1.27× |
| 重复性文本，k=5 | 3.67 | 56.3% | **1.58×** / 1.27× |
| 开放式文本，k=5 | 1.33 | 22.9% | 0.99× / 0.89× |

区间是 **0.89–1.58×**，明显低于论文里的 2–3×。原因三个，都记在 JSON 里：

1. **机器被占用**：这轮实验时同一张卡上还有别的任务在跑。
   每组的重复测量散布（`reps_speedup_spread`）是 **1.44–1.85**，
   说明单次测量的噪声与效应同量级。**所以"最优 1.58×"与"均值 1.27×"差距这么大，
   不是实现不稳，是环境不稳。**
2. **我的实现多付了一次前向**：为了在每轮后恢复 next-token logits，
   我把最后一个输出 token 喂回去又跑了一次 1-token 前向。
   真实引擎里 logits 是从验证前向直接取的，不该有这笔开销。
3. **草稿器太弱**：prompt-lookup 在开放式文本上接受率只有 22.9%，
   而公式告诉我们 α=0.23 时上界就是 1.3×。

所以我在论文对照表里**不写"我实现了 2–3×"**，而是写明
"在 6 GB 单卡 + 弱草稿器 + 被占用的机器上，实测 0.89–1.58×，
且与 α=0.23 处的上界 1.3× 同向"。这才是能对上的说法。

一个附带发现也该记下来：`predicted_speedup`（用隔离测得的前向成本曲线算出的预测值）
与实际测得的加速比同向但偏高（预测 1.48/1.76/1.00，实测 1.21/1.58/0.99）。
它是**交叉验证工具，不是结论**。

## 6. 论文基线（注意各自的硬件与前提）

| 工作 | 报告加速 | 硬件 / 前提 |
|---|---|---|
| Leviathan et al. 2023 (arXiv:2211.17192) | 2×–3×（T5-XXL，输出完全一致） | TPU；草稿 T5-small 77M |
| Chen et al. 2023 (arXiv:2302.01318) | 2–2.5×（Chinchilla 70B + 4B 草稿） | 16×TPU v4；"within hardware numerics" |
| Medusa (arXiv:2401.10774) | 2.2×（Medusa-1）/ 2.3–2.8×（Medusa-2） | Vicuna 7B/13B，A100 80GB 仿真 |
| EAGLE (arXiv:2401.15077) | 2.7–3.5×（LLaMA2-Chat 70B）/ 2.1–3.8×（MT-bench） | RTX 3090 24GB（7B）；4×A100（70B） |
| EAGLE-2 (arXiv:2406.16858) | 3.05–4.26× | 相对 vanilla AR；论文未写明基准 GPU |

两个提醒：
- **EAGLE 在 Mixtral 8×7B 上只有 1.5×**（论文 Table 3）。MoE 的每个 token 激活的
  专家不同，草稿的"特征"参考价值下降——MoE + 投机解码不是简单叠加。
- EAGLE-2 的正确 arXiv 编号是 **2406.16858**；常被引作 2404.18911 的那篇是
  *Kangaroo*（自投机，1.68×），两者不是一回事。

## 7. 局限

- **没有 EAGLE 式训练**。EAGLE 的收益来自"在特征层训练一个单层草稿头"，
  这需要训练流程，本仓库只做了推理侧的验证与调度。
- **树状注意力的验证只到 mask 正确性**，没有接真实模型跑 tree verify 的吞吐。
- **端到端数字不可用于对外宣称**（机器被占用、实现多一次前向）。
  能对外说的是：正确性检验、α–k 拐点、以及分段接受率这三个结论。
- **没有做 draft 的批量化**：一次验证里多个请求的草稿长度不一致时，
  需要 padding 或 varlen，本仓库按单请求处理。
